# SqueezeCare

A design research case study and concept proposal for supporting international young people living alone when they feel unwell.

**Project:** Team LuckyDogs, Design Computing Studio 3, 2026  
**Focus:** UX research, tangible interaction, remote social support, and communication assistance  
**Status:** Concept-design project; no executable application or working interactive device

![SqueezeCare proposed handheld companion](assets/concept-sketch.png)

## Project Overview

SqueezeCare proposes a soft handheld object that lets a user request support with a squeeze and receive a tactile acknowledgement from another person. A separate, optional voice interaction would help summarise and translate the user’s symptom description for later communication.

The concept addresses the effort involved in reaching out when someone is alone, physically uncomfortable, or unsure how to explain their situation in another language. Its final scope centres on reassurance and communication assistance. Diagnosis, urgency assessment, and automated medical decisions are outside that scope.

## Research at a Glance

| Activity | Evidence documented |
| --- | --- |
| Preliminary research | Two early interviews about living alone and night-time care access. |
| Main team interview study | 18 participants; analysis through open coding and affinity mapping. |
| Technology and privacy questionnaire | 37 valid responses. |
| Support-needs questionnaire | 19 responses in the final-report and personal-portfolio snapshot. |
| Exploratory object-preference study | Eight participants; seven usable records analysed. |

The object comparison used existing physical objects. It investigated preferred interaction qualities rather than testing a working SqueezeCare prototype.

## Iteration 3 Highlights

- The design question shifted towards feeling supported in an unfamiliar environment.
- In the 19-response survey, 78.9% said that receiving a response could reduce their stress; this was a reported preference, rather than a measured effect of SqueezeCare.
- 73.7% reported difficulty describing symptoms clearly and the same proportion worried about using incorrect English words.
- Five of seven usable interaction-study records favoured a squeezable object first, informing the proposed soft, rounded handheld form.
- The final concept separates a lightweight support signal from optional voice-assisted symptom communication.
- Ethical requirements emphasise deliberate activation, user-controlled recipients, limited disclosure, and a restricted role for AI.

## Proposed Interactions

| Input or event | Intended behaviour |
| --- | --- |
| Light squeeze | Send a minimal support request to an agreed recipient. |
| Supporter’s response | Return a tactile acknowledgement; light feedback is also proposed. |
| Squeeze pattern | Represent aspects of rhythm, pressure, and duration in the tactile response. |
| Longer squeeze | Start guided voice input for symptom summarisation and translation. |
| Summary generated | Make the translated description available on the user’s phone. |

All behaviours are proposed. No firmware, connected service, validated gesture thresholds, or translation engine was built within this project.

## Further Work

Future work would need to test squeeze mappings and accidental activation, distinguish system receipt from human response, address requests that receive no reply, and evaluate the clarity of translated summaries. Device comfort, privacy controls, and the feasibility of the proposed sensing and feedback also remain open.
